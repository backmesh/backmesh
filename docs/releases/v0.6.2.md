Upgrade with `backmesh upgrade`; there's no need to uninstall.

### Changes

- **First use installs the right package.** On first use, `psql` and the other PostgreSQL client commands now install the client; until now they installed only its wrapper, which failed. `dotnet` now installs the .NET 10 SDK, not a host without an SDK. Commands that would install the wrong tool now fail as not found, as they do on any runner without them: `swift` installed OpenStack's client, `firefox`, `chromium-browser` and `chromedriver` installed Ubuntu's snap stubs, which can't run in the runner's container, and `bazel` installed Bazel 4.2.3, which ignores `.bazelversion`.
- **`gh` and Docker match GitHub's image.** The runner image now has GitHub CLI 2.105.0, from GitHub's release, instead of Ubuntu's 2.45.0, so `gh attestation` and `gh api --slurp` work. It also has Docker CLI 28.0.4, Buildx 0.39.1 and Compose 2.38.2, up from 27.5.1, 0.20.1 and 2.33.0. docker/setup-buildx-action uses the runner's Buildx unless a workflow sets a `version`.
- **GCP's on-demand labels try AMD's newest VMs first.** `backmesh-od-4`, `backmesh-od-8` and `backmesh-od-16` on GCP now try `c4d` (Zen 5), then `c3d` (Zen 4), before `n2` and `n2d`; `backmesh-od-2` doesn't change. At 4 vCPUs, `c4d` built in half of `n2`'s time, at 0.78 of its cost per job with its Hyperdisk Balanced disk, and `c3d` in 0.71 of it at 0.76. A `c4d` VM has 3.875 GiB of memory a vCPU, so `backmesh-od-4` may get 15 GiB, not 16. `us-south1` offers neither, and `us-west2` and `us-west3` no `c3d`, so jobs there start on `n2` or `n2d`. Spot and KVM labels don't change. On-demand runners now also count against GCP's `C4D_CPUS` and `C3D_CPUS` quotas, which install names with the others to raise, and a `c4d` runner's disk against the region's Hyperdisk Balanced quotas.
