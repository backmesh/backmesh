Upgrade with `backmesh upgrade`; there's no need to uninstall.

### Changes

- **Azure's always-on VMs fall back to another size.** Some Azure subscriptions may not create `Standard_B2s` in any region (`NotAvailableForSubscription`), so install stopped in every region with "Azure won't create the listener VM (Standard_B2s)". The listener VM now takes the first size the region offers your subscription from `Standard_B2s`, `Standard_B2als_v2`, `Standard_B2ls_v2`, `Standard_B2as_v2`, `Standard_B2s_v2`, `Standard_D2as_v5`, `Standard_D2s_v5` and `Standard_D2s_v4`, and the control plane's VM from `Standard_D2s_v5`, `Standard_D2as_v5` and `Standard_D2s_v4`. A size whose family quota has no room gives way to the next. The plan prints each VM's size and monthly price, in each region install may fall back to. A listener VM keeps its size: when `backmesh upgrade` replaces a lost one, the new VM takes the old one's, and a listener moving off `bm-control` takes its Node's.
- **One Azure region's sizes are read alone.** With `--control-plane azure:<region>` outside backmesh's US regions, or a control plane resumed in its own region, the plan reads `az vm list-skus` for that region only, instead of Azure's whole catalog.
- **The Azure page names both GPU labels.** `backmesh-gpu-t4` runs on spot and `backmesh-gpu-od-t4` on demand; the page had named one GPU label and called it on-demand.
