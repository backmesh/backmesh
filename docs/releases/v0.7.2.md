Upgrade with `backmesh upgrade`; there's no need to uninstall. `upgrade` lists the new arm64 labels and asks before it creates them.

### Changes

- **Spot labels fall back to on-demand on their own.** When spot capacity is refused in every runner region, jobs start on demand (billed at on-demand rates) and return to spot after 30 minutes. ([#159](https://github.com/backmesh/backmesh/pull/159))
- **Runners in the EU.** `backmesh install --runner-geo eu`, or `backmesh upgrade --runner-geo eu`, runs an org's runners and their cache in EU member states' regions only, such as GCP's `europe-west4`; the default stays `us`, and a re-run or an upgrade keeps the org's geo. `--runner-region <cloud>:<region>` starts a cloud's jobs in one of the geo's regions first, near their cache, with the geo's others as failover. ([#158](https://github.com/backmesh/backmesh/pull/158))
- **High-memory labels.** `backmesh-ubuntu-2404-highmem-2vcpu` to `-16vcpu`, and their on-demand twins `backmesh-ubuntu-2404-highmem-od-<n>vcpu`, have 8 GiB a vCPU: AWS `r8a` to `r6a`, GCP `n2-highmem` and `n2d-highmem`, Azure `E<n>ads_v5` to `E<n>s_v5`. `backmesh upgrade` adds them; on Azure, the on-demand ones also need an E-series family's vCPU quota. ([#158](https://github.com/backmesh/backmesh/pull/158))
- **`~/.cargo` is Cargo's.** The runner moves `HOME`, so a `backmesh/cache`, `actions/cache` or `Swatinem/rust-cache` of `~/.cargo/registry` cached a directory Cargo never wrote to. `~/.cargo` and `~/.rustup` now link to Rust's homes in the image. ([#161](https://github.com/backmesh/backmesh/pull/161))
- **arm64 runners on AWS and GCP.** `backmesh-ubuntu-2404-arm-2vcpu` to `backmesh-ubuntu-2404-arm-16vcpu` are spot VMs at the same sizes and 4 GiB a vCPU as the other labels: AWS Graviton4's `m8g`, then Graviton3's `m7g`; GCP Axion's `c4a-standard`, then Ampere's `t2a-standard`. `backmesh-ubuntu-2404-arm-highmem-<n>vcpu` have 8 GiB a vCPU: AWS `r8g` then `r7g`, GCP `c4a-highmem`. Each has an on-demand twin, `-arm-od-<n>vcpu` and `-arm-highmem-od-<n>vcpu`, and a label on a cloud other than the control plane's names it, as `backmesh-gcp-ubuntu-2404-arm-4vcpu`. An arm64 label launches only in the runner regions that offer one of its types: GCP's `t2a` is in few, `c4a` in most, so a job fails over to another of the geo's regions where its first has none. Jobs that build arm64 images under QEMU, or run on GitHub's `ubuntu-24.04-arm`, run natively there. anycloud measured backmesh's builds on `m8g` at 0.94 of `m8i`'s time at 4 vCPUs and 1.03 at 16, at 0.85 of its on-demand price ([anycloud#36](https://github.com/anycloud-sh/anycloud/pull/36)). Spot Graviton is scarcer than spot x86 at 4 vCPUs (42 % of zones took a spot `m8g.xlarge` against `m8i.xlarge`'s 81 %); an arm64 spot reclaim or refusal moves only the arm64 labels onto their on-demand twins. Azure gets none: its catalog lists `Dpsv5` and `Epsv5`, but anycloud boots the arm64 image only on AWS and GCP, and install says so. ([#131](https://github.com/backmesh/backmesh/pull/131))
- **The runner image is built for x86-64 and arm64.** One signed index names both, so every label pulls the same digest and gets its VM's build. Each pinned tool has its arm64 release, checked against its own SHA-256, and the first-use installs (the cloud CLIs, Rust, PowerShell, Go, Java, and Chrome and ChromeDriver from Chrome for Testing's `linux-arm64` build) fetch arm64 releases on arm64. Pull requests run the image's checks on both. ([#131](https://github.com/backmesh/backmesh/pull/131))
