Upgrade with `backmesh upgrade`; there's no need to uninstall.

### Changes

- **The package managers' caches restore in the background.** GitHub tells backmesh that a job started a median 12 seconds into the job, and only then does the job get its cache token, so with v0.5.4's 10-second wait most jobs restored nothing. Set up runner now waits only for the tools, which `setup-*` steps look for at once. The npm, Yarn and pnpm caches go on waiting for the token, up to 2 minutes, and restore as the job's first steps run. A step that makes the cache's directory first keeps its own, and a restore never leaves a half-written directory. Complete runner prints each background restore's line, such as `backmesh cache: auto restored yarn (own)  812 MB in 9.1 s, at +23.4 s`, or that it gave way to a step or gave up.
- **A cache restored after the install isn't saved as the new lockfile's.** A cache restored from an older lockfile is saved under the new one only if the job's install wrote into it.
- **Yarn 1's cache holds only what the lockfile uses.** Yarn 1 keeps every version it ever fetched, so a long-lived cache grows to several gigabytes. Its save now leaves out the entries the job's `yarn.lock` files don't name. An entry already saved shrinks at its next save, when the lockfile changes. npm's and pnpm's caches are saved whole, as before.
- **Set up runner's cache summary reads the token's time.** Since v0.5.4, the summary line said `no cache token` even after a job's restores, as it couldn't read the time the restorer wrote.
