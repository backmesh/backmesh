Upgrade with `backmesh upgrade`; there's no need to uninstall. Install the CLI with `curl -fsSL https://backmesh.com/install.sh | sh`.

### Changes

- **Caches in your own cloud.** `backmesh install` and `upgrade` create a cache bucket in each runner region. Swap `actions/cache` for `backmesh/cache@v1`: same inputs, restores fetch in parallel, and saves upload after the job. `--cache-cap` sets each repository's limit, 10 GB by default.
- **Automatic caches.** With no workflow change, a job restores the toolchains and npm, Yarn or pnpm caches it used last time. Folders a workflow already caches are left alone. Set `BACKMESH_AUTO_CACHE: false` to turn it off.
- **`docker kill $(docker ps -q)` no longer kills the runner.** The runner's own container is hidden from `docker ps` and skipped by `kill`, `stop` and `rm`.
- **Closer to `ubuntu-latest`.** `apt-get install` works without `apt-get update` first; the tool cache is writable; `LANG`, `ImageOS` and `/usr/games` match; `/dev/shm` is half the runner's memory. See [Coming from ubuntu-latest](https://backmesh.com/from-ubuntu-latest/).
- **Sign-in is GitHub's device flow only.** `install` prints a code for github.com/login/device; the connect pages are gone and `--device` is no longer an option.
- **Faster starts.** The runner image uses zstd layers, runners start before the listener's housekeeping, and a launch that the cloud refuses moves to another region after 75 s instead of 3 minutes. Pins anycloud 0.1.77, which pulls the runner image with parallel unpacking.
- **Cue results in `backmesh status`.** Start waits are split by what started the runner: a cue, a prediction or the job itself.
- **Every reclaimed run gets a note.** A run that lost a spot VM gets a `backmesh: reclaims` check run explaining the rerun.
