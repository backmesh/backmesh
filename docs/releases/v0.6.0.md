Upgrade with `backmesh upgrade`; there's no need to uninstall. An installation from before v0.5.0, whose listeners still share the `bm-control` node, runs `backmesh upgrade` with backmesh v0.5.5 first, which moves each listener to its own VM, then upgrades with this release; this release doesn't move them.

### Changes

- **The control plane moves to anycloud 0.1.82.** anycloud 0.1.81 removes node pools and Kubernetes Deployments, which backmesh no longer uses: each org's listener has run on its own VM since v0.5.0. backmesh drops the code that moved a listener off `bm-control`, and `install` and `uninstall` create and delete the control plane with `anycloud api create` and `anycloud api delete`.
- **Runners launch in their own network, and `upgrade` re-applies each cloud's role.** anycloud 0.1.81 starts each runner's VM in an anycloud-owned network (the `anycloud-jobs` VPC on AWS and network on GCP) instead of the account's default one, so a runner no longer reaches other machines there. Its role needs new rights for that: on AWS `ec2:CreateVpc`, `ec2:CreateSubnet`, `ec2:CreateInternetGateway`, `ec2:AttachInternetGateway`, `ec2:CreateRoute`, `ec2:DescribeAvailabilityZones`, `ec2:DescribeInternetGateways`, `ec2:DescribeRouteTables` and `ec2:DescribeSubnets`, and on GCP `compute.networks.create` and `compute.networks.get`; Azure's is unchanged. `backmesh upgrade` re-applies the AWS and GCP role setup through your cloud CLI right after it updates the control plane, before any listener restarts. Before you run it, sign `aws` in to the account install used. Sign `gcloud` in to any account that can reach the project, with a default project set (`gcloud config set project`). upgrade checks both before the control plane moves. `--plan` names each role once the control plane is on 0.1.82. It refuses while the control plane is behind. A run that stops there says how to finish. A cloud connected with keys (`--generate`) has no role to re-apply, so `upgrade` prints the command that grants its identity these rights. Run it once, signed in to the account or project install used.
- **If you also use the anycloud CLI on this control plane:** `anycloud cluster create` and `anycloud cluster delete` are now `anycloud api create` and `anycloud api delete`, with the same options. `anycloud node-pool` and `anycloud deployment` are gone. backmesh runs its own pinned anycloud, so nothing changes for `backmesh` commands.
