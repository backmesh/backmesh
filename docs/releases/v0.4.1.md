Upgrade with `backmesh upgrade`; there's no need to uninstall.

### Changes

- **Several installations per cloud account.** A new installation names each cloud connection for its control plane, such as `bm-aws-k4nktn`, so two installations in one AWS account, GCP project or Azure subscription no longer collide, and a reinstall after `backmesh uninstall` works. Existing installations keep `bm-aws`, `bm-gcp` and `bm-azure`.
- **`uninstall` deletes the identities install generated.** Where install generated a cloud identity for a connection, `uninstall` deletes it, with its keys and grants, through your cloud CLI once the control plane is gone. If your CLI can't, it prints the commands that do.
- **Reading an org's ID uses your GitHub token.** Install, upgrade, `status` and `rotate-key` send `GITHUB_TOKEN`, else `GH_TOKEN`, when reading an org's ID, so a GitHub-hosted runner's shared IP no longer hits GitHub's anonymous rate limit, and a rate-limited read says so. The read needs no scope, and if GitHub rejects the token, it retries without one.
- **Several orgs share one control plane.** Install and upgrade give each org's listener half a vCPU of `bm-control`'s Node, so a second org installed on 0.4.1 finds room, and `backmesh upgrade` sets the share on listeners created before. If a second org joined before 0.4.1 and its listener stayed Pending, `backmesh upgrade` refuses because that listener doesn't answer. Run `backmesh uninstall --org <org>` for that org, then `backmesh upgrade`, then `backmesh install` for it on 0.4.1.
