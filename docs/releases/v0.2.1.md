Upgrade with `backmesh upgrade`; there's no need to uninstall.

### Changes

- **KVM labels.** Jobs that start microVMs, emulators or other virtual machines can use `backmesh-kvm-2` to `backmesh-kvm-16` and get `/dev/kvm`. Each cloud gets two more pools, `bm-<cloud>-kvm-spot` and `bm-<cloud>-kvm-od`, whose VM types support nested virtualization: `m7i.4xlarge` and `m8i.4xlarge` on AWS, `n2-standard-16` and `c2-standard-16` on GCP, and `Standard_D16as_v5` and `Standard_D16s_v5` on Azure. Like the other pools, they idle at zero VMs. A job reclaimed on spot reruns on demand, and `backmesh-kvm-od-<n>` always runs on demand. With several clouds the labels name the cloud, such as `backmesh-aws-kvm-8`. A region that offers none of these types gets no KVM labels. The KVM pools share their cloud's spot and on-demand vCPU quotas with the other pools. `backmesh upgrade` creates them on an existing installation. Every job on a KVM VM can open `/dev/kvm`.
- **Uninstall exits cleanly.** A full `backmesh uninstall` that deleted the control plane no longer exits 1 with an `api use` error, so its final report of leftovers prints. When the recorded control plane doesn't answer, uninstall goes on to the unreachable-control-plane path instead of failing first.
- **Usage events name the cloud.** Usage events now name the cloud of on-demand and KVM jobs, which v0.2.0 reported as unknown.
