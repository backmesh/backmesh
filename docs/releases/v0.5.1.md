Upgrade with `backmesh upgrade`; there's no need to uninstall.

### Changes

- **Install prints the labels to use.** The plan and install's end list this installation's labels exactly; the control plane's cloud's carry no cloud, so an Azure control plane's GPU label is `backmesh-gpu-t4`. Install ends on the largest label up to `backmesh-4` that your quotas start a runner for, or says none does.
- **Quotas count jobs per region.** The plan's "jobs at once" counts what each region's quota fits, so 3 spot vCPUs in every region show 0 `backmesh-4` jobs, not several.
- **Azure's size check waits for a slow `az`.** The plan reads Azure's VM sizes for up to 3 minutes, twice, and stops with the reason if it still can't, instead of trying the first region unchecked. A create refused for "exceeding approved" quota moves to the next region too.
- **A stopped install's control plane gets its delete command.** When the plan finds a control plane named `backmesh` with no VM, it says so and prints the cloud CLI command that deletes it.
- **Uninstall deletes its own control plane while another installation runs.** With a control plane configured, `uninstall` deletes it, revokes its install and removes its own scale sets, runners and runner groups, even while another backmesh installation in the org has used the App in the last hour. An org with control planes in two clouds or regions can now remove one. The App stays in the org for the other installation; uninstalling the last one removes it.
- **Public repositories the runners refuse are named.** Without `--public-repos`, an org's runner group refuses its public repositories, and their jobs waited at GitHub with no word. The install and upgrade plans and `backmesh status` now say how many there are, with one by name, and `backmesh upgrade --public-repos` adds `backmesh-public-2` and `-4` to an existing installation.
- **Install waits for GCP's new role trust.** GCP can refuse a token at a workload identity provider for a minute or two after it's created (`invalid_target`). Install now makes the GCP role connection again for up to 2 minutes on that error, then stops with GCP's reason.
- **Uninstall deletes the control plane of a failed install.** When install stopped before its listener started, `uninstall` had no install key, backmesh.com refused its GitHub cleanup while another installation of the org was live, and the control plane kept running. Now `uninstall` deletes the control plane, its runner VMs, cache buckets and connections anyway. Only the org's GitHub cleanup is skipped: with no listener ever run, nothing of the install is there; a listener's runner groups are named for you to delete in the org's Actions settings, and the command exits non-zero.
